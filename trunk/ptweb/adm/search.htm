Search Engine

Currently, we use Htdig

htdig installation notes

  1. PDF files get searched if acroread can be found as /usr/local/bin/acroread
  2. When building htdig, be sure that the binaries can find all of their shared libraries. I had to edit Makefile.config.in and add the -R argument: 
    LDFLAGS=	@LDFLAGS@ $(LIBDIRS) -Wl,-R/usr/local/apache/htdig/lib
  3. You should run configure on brahe so that the pathnames are set up properly. Definitely don't run it on messier, or you may get /export in your paths
  4. Configure with: 
    ./configure -prefix /usr/local/apache/htdig
  5. Run make, then make install
  6. Copy htsearch: 
    cp htsearch/htsearch /usr/local/apache/share/cgi-bin
  7. Run ldd htdig/htdig and then copy the libstdc++ shared library to /usr/local/apache/htdig/lib 
    cxh@carson 16% ldd htdig/htdig

	libsocket.so.1 =>	 /usr/lib/libsocket.so.1
	libstdc++.so.2.9.0 =>	 /users/cxh/pt/gnu/sol2.5/lib/libstdc++.so.2.9.0
	libm.so.1 =>	 /usr/lib/libm.so.1
	libc.so.1 =>	 /usr/lib/libc.so.1

cxh@carson 17% mkdir /usr/local/apache/htdig/lib
cxh@carson 18% cp /users/cxh/pt/gnu/sol2.5/lib/libstdc++.so.2.9.0 /usr/local/apache/htdig/lib
  8. We have two search engine databases:
    1. A database consisting of all of the publically available pages: This search is controlled by
    2. A database consisting of all of the publically available pages, and the group pages that are protected by hostname.
  9. The database files reside on messier in /vol/messier/messier1/htdig
  10. /usr/local/apache/conf/htdig.conf controls the engine for the public pages and the protected pages
    The database_dir should be set to: 
    database_dir:		/vol/messier/messier1/htdig/db
    I edited it and commented out start_url and added: 
    start_url:		http://ptolemy.eecs.berkeley.edu/
    I also added /private/ to exclude_urls 
    exclude_urls:		/cgi-bin/ .cgi /private/ /CVS/ .rpm .zip .jar .ps /RCS/ /SCCS/ /tmp/ /bak/ .gz .tar split
    maintainer was also changed: 
    maintainer:		www@ptolemy.eecs.berkeley.edu
  11. /usr/local/apache/conf/htdigpub.conf controls the engine for the public pages.
    The only difference between htdig.conf and htdigpub.conf is that htdigpub.conf uses a different database 
    database_dir:		/vol/messier/messier1/htdig/dbpub
  12. /usr/local/apache/htdig/bin/rundig is the script that is run that creates the database.
    Change DBDIR to point to the database_dir 
    DBDIR=/vol/messier/messier1/htdig/db
  13. /usr/local/apache/htdig/bin/rundigpub is the script that is run that creates the public only database.
    Change DBDIR to point to the database_dir 
    DBDIR=/vol/messier/messier1/htdig/dbpub
    Set opts so that it always includes the public config file 
    # This will add lots of debugging output to all of the programs
stats= opts= alt=
opts="-c /usr/local/apache/htdig/conf/htdigpub.conf"
  14. We modified the html files in /usr/local/apache/htdig/common so that they use the Ptolemy website style sheets. One thing to note is that we used an absolute path for the default.css files
  15. There are two files that need to be initialized by running htdig. 
    cxh@carson 81% ./htsearch

Public htdig database

  • The public htdig search page is at http://ptolemy.eecs.berkeley.edu/htdig/searchpub.html
  • The htdig database is updated twice a week by the majordom user on forney. See /usr/local/adm/cron.htdigpub. Forney is not included in the /usr/local/amanda/htaccess/ohmCluster page, so the non-public group pages are not included in the Public only database.

    • Public and group htdig database

  • The public and group htdig search page is at http://ptolemy.eecs.berkeley.edu/~ptdesign/htdig/search.html
  • The htdig database is updated three times a week by a cronjob run by the majordom user on messier. See /usr/local/adm/cron.majordom

    • Running the engine by hand

    The htdig search engine is run as a cron job from by the majordom user on messier. As root on messier, you can use crontab -l majordom to see the command to run htdig. If you run htdig, you must su first to majordom on messier. 

    su - majordom
/opt/www/htdig/bin/rundig -v >& /tmp/htdig2.out &

    Htdig problems

  • Check the log files in /tmp
  • Make sure that you have not run out of disk space. 
    df . | grep dev
    If the disk filled up, look at /tmp/htdig.out (careful, it is big) and then add any bogus directories to ~ptdesign/adm/www/robots.txt
    The rerun the search engine by hand
  • If you have links that end in question marks, then htdig gets bogged down and fails to finish. The classic example of this is to have a header in a file that ends in a question mark, and then have a link to that target.
  • To test the search engine from a Unix prompt, pass in the appropriate configuration file: 
    cxh@carson 102% /usr/local/apache/share/cgi-bin/htsearch -c /usr/local/apache/htdig/conf/htdigpub.conf
Enter value for words: object
Enter value for format: long
